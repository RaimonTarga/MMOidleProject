# Work required before launch

This is a preparation backlog with pass conditions, not an executable launch approval.

1. **Resolve pacing criteria.** Save user-provided tier and biome duration bands before viewing outcomes if pass/fail judgments are wanted. Descriptive measurement can proceed without bands once technical gates pass, but cannot declare target compliance.
2. **Resolve canonical inputs.** Preserve the eight rejected historical T2 inputs and errors. Obtain fresh current-definition earned 1× handoffs for each actor, or designate compatible existing inputs with full lineage validation. Obtain actual completed-T2/T3 entries for T3/T4. Separate prerequisite acquisition from measured tier lives. Preserve exact inherited wallets; no synthetic grants, ownership repair, best-result selection or unrecorded migration.
3. **Resolve route authorities.** T1/T2 candidates are exported. Qualify them against current definitions and their exact inputs. Prepare explicit farm-step watchdog limits. Define full T3/T4 routes only from established canonical acquisition/purchase plans; unsupported actor/tier cases remain missing. Name the T4 terminal milestone before sealing. Do not reuse short encounter continuations as full progression lives.
4. **Resolve restoration semantics.** Either use a currently eligible authoritative continuation path that preserves the required state, or implement/test an explicit eligibility contract for earned named restores. Keep synthetic lineage disqualifying and report skipped-prefix costs honestly. Never postprocess `economyEvidenceEligible=false` into true.
5. **Qualify a fixed-profile rate adapter.** Separate player tier from target tier. Prove two isolated worlds start from identical persistent state and original input hash remains unchanged; no target-tier loadout materialization. Prove normal reward path, fractional catalyst accounting, natural deaths/respawns/repopulation, XP cap semantics, window timing and no purchases. Handle travel/measurement boundary equality explicitly. Resolve profile-legal reachability and ability/stance/Rite/upgrade catalyst/colour demand coverage. Record exclusions before sealing.
6. **Resolve schedule and resources.** Four P lives plus R requires five concurrent worlds. Current limit is four and FIFO cross-cohort scheduling does not provide fairness. Either qualify revised scheduling/capacity for this exact workload before launch, or obtain a changed campaign schedule that preserves independent tier entries and explicitly relaxes simultaneous-start requirements. Do not silently run P tiers serially or launch independent supervisors to evade the global cap. Monitor CPU, memory, event-loop lag, worker heartbeats and disconnects; seal numeric thresholds and stop behaviour from actual resource qualification before launch. A successful older short qualification is not approval for this larger workload.
7. **Seal only after qualification.** Record full committed source/tree, tooling hash, immutable image/build ID, route versions and complete resolved steps, actor specialization/loadout, input and restore-state hashes, run order, exposure identities, times/caps, resources, output paths, metric schema and R3 selection rules. Launch-time develop drift triggers a fresh reviewed preparation/qualification, never mixed revisions. The preparation hashes are not this seal. Every worker must have its own raw directory and private world/database identity.
8. **Run only on execution instruction.** No measured lives, source changes, purchases, merge or deployment occurred in this preparation. On later execution, use the established frozen isolated runner once eligible; keep failed/partial/not-run evidence, no automatic retry, no tuning. Start the independent blocks under the resolved shared schedule; R3 can overlap ongoing P.
9. **Close out.** Reconcile manifest versus all terminal states and raw hash inventory before publishing six requested reports. Report completion/censoring, provenance and telemetry eligibility per case, criteria separately from measured values, and at most five exact candidate levers. Preserve external raw artifacts after terminal service release.

## Existing commands (reference, not ready launch commands)

The intended runner is `scripts/experiment/cli.mjs` (`experiment:create`, `launch`, `status`, `report`, `release`) plus `queue-add` / `queue-run` only after scheduling is resolved. `experiment:create` builds committed sources and ignores uncommitted route changes. The complete campaign is **not** representable by passing the current ordinary farm matrix and 32 route names to these commands. No placeholder launch script is supplied that could accidentally start invalid cases.
