## Code review

`/code-review high`, run twice (see Divergences).

**This run's code — five findings, all confirmed at the seam and all fixed** (`878e29c7`,
`f8cd78ba`):

1. **Immovable held plating stacks permanently.** The movement clock was written inside
   `runStationaryDr`, which returns early for a player wearing no stationary-DR item — so
   the keystone's plating half did nothing for most builds, and a player who lost the
   passive while moving froze the clock inside the grace window, where
   `immovableHoldsPlating` stayed true and the plating fade never ran again. The clock is
   now advanced at the top of `runStationaryDr`, above its early returns.
2. **An ability node paid once per summon.** A Conduit formation Technique reaches
   `applyTechniqueRider` once per living summon, each carrying a share of one armed
   payload; the node's packet payoff fired on every one at full magnitude while the
   rider's own damage was weight-divided. It now fires on the claim that completes the
   payload — the "ONCE PER LANDING" contract the hook's own docblock states.
3. **A `targets`-amplified echo chained once per body.** `runChain` sat in `applyOnTarget`,
   which `applyPayoff` calls again per amplified neighbour, so the Tempo keystone started
   1+extra independent chains of up to `chainMaxLinks` each, with separate `struck` sets
   letting them re-hit each other's bodies. Started once per application now, from the
   primary body.
4. **A refused node purchase left persisted junk.** Progress was materialised and
   `tracksProgression` dirtied before the check ran, so every rejected
   `ability:unlockNode` broadcast and saved state it had not earned.
5. **The T1 mask lost its node-count guard.** Dropping `modifier` skipped the per-modifier
   tally, which was also what pinned each biome's node count against the hand-cut mask;
   the per-tier total cannot see a cell moved between biomes because the two errors
   cancel. Pinned per biome now, and it refuses to pass silently on a tier whose biomes
   are not all the same size. Verified non-vacuous.

Finding 1's fix also gained the regression the bug deserved, in `keystones.test.ts`
(verified non-vacuous by stubbing the predicate to false).

**Pre-existing branch code — seven findings, NOT fixed.** Outside this run's scope, and
several turn on balance decisions the overnight report already escalated. Recorded here so
they are not lost:

1. `lineageCards.ts` `plating-shred` resolves a **total** reduction but writes it to
   `data.platingReduction`, which `effectivePlatingAfterShred` multiplies by stack count —
   sharing the record with the cadence finisher's 3-stack brand triples the strip.
2. `cadence/t3/pipeline/empoweredHit.ts` — the Cursed Finale was never migrated to
   `applySharedDebuffMaxWins`, so card-first ordering leaves its `vulnerability` and its
   *permanent* `plating-shred` overwritten by the card's weaker timed single-stack values.
   The helper protects one ordering and the test covers only that one.
3. `combat/status/sharedDebuffRecord.ts` — `Math.max(effect.remainingMs, priorMs)` with
   `remainingMs === -1` clamps a **new permanent** application down to the prior finite
   window, contradicting the function's own "-1 beats every finite window" contract.
4. `summoner/frameLoop.ts` — Effigy's `frame.summoner.link` record carries no owner in its
   id, so two Conduits on one body wipe each other's pair and kill credit goes to whoever
   wrote last.
5. `lineageCards.ts` — the `evade` trigger gates on `metadata.evaded`, which is also set

   so the card procs on hits that landed and fires alongside `hit-taken`.
6. `db/playerRepo.ts` — `refundWeaponUpgradeEssence` runs inside `hydratePlayerSlices`,
   which `listAccountCharacters` and the admin listing also use read-only: the refund log
   fires on every lobby load and the mutation is discarded.
7. `lineageCards.ts` — `updateLineageCards` computes `isPlayerActivelyInCombat` (an
   `aggroedMonsters` scan) unconditionally per live player per tick, before checking for
