### The kept engine API (what the class runtimes call)

`server/src/systems/player/abilities/abilityFiring.ts`:

```ts
fireTechnique(world, player, abilityId, now, options?: {
  currentTargetOnly?: boolean;   // the player's current attack target only, no fallback
  chargeAtAnyRange?: boolean;    // skip Charge's gap gate (a caller that picked its moment)
}): { activated: boolean; claimed: boolean }   // stop offering non-instant ones once claimed
fireGuard(world, player, abilityId): boolean   // true when it activated (one per 100 ms window)
```

Both keep every gate: per-ability cooldowns, hard control / channeling / root, the one offensive
channel, the one-Guard window, and the situational gates (Cleanse needs a debuff, Break Free control,
a Recovery Guard missing HP, Sidestep a threat in reach, Contagion work, a reposition somewhere to go).
Underneath, unchanged: `abilityCasting.ts` (`beginAbilityCast`, `updateAbilityCasts`,
`updateAbilityCharges` — still run by `World.tick` — `cancelAbilityCast`,
`holdsPositionWhileCasting`, `castWindupFor`), `abilityArming.ts` (`armTechnique`),
`formationCharge.ts`, `abilityAffliction.ts` (`resolveContagion`, `copyPlayerDotOnto`,
`resolveDetonate`, `afflictionTechniqueHasWork`, ...), `abilityImbue.ts`, `abilityBramble.ts`,
`abilityBuffs.ts` (`ABILITY_BUFFS`), `abilityEffects.ts` (`initAbilitySystems`,
`resolveCastPayload`, `cullMultiplier`, ...), `abilityTargeting.ts` (`abilityTarget`,
`abilityEngagementRange`, `gapToTarget`, summon casts), `abilityCooldowns.ts`, `abilityKata.ts`,
